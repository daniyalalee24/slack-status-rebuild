# Guide for the Next Contributor\n\nThis project is a small React + Vite rebuild of Slack's Set a status modal. The UI is kept close to Slack, while the project adds a permanent Favorites list for recurring statuses.\n\n## Project layout\n\nslack-status-rebuild/\n  public/                 Static public files\n  src/\n    components/\n      StatusModal.jsx     Main status modal and feature logic\n    App.jsx               Page-level state and active-status display\n    App.css               App-specific CSS\n    index.css             Global CSS entry\n    main.jsx              React/Vite entry point\n  eslint.config.js        ESLint rules\n  vite.config.js          Vite configuration\n  package.json            Scripts and dependencies\n  README.md               Setup and project overview\n\n### Why it is laid out this way\n\nmain.jsx only mounts the React application. App.jsx owns the currently active status and controls whether the modal is open. This keeps page-level state separate from the modal.\n\nStatusModal.jsx contains the main feature behavior: editing a status, emoji selection, duration selection, Recent statuses, Favorites, validation, keyboard handling, and modal dismissal.\n\nThe project currently keeps these behaviors together because the feature is self-contained. If the modal grows substantially, parts such as the status list, duration controls, or emoji controls can be extracted into separate components.\n\n## Where a new feature should go\n\n### Changes to the active status display\n\nWork in src/App.jsx when the feature affects the active status display, opening or closing the modal, clearing the active status, or persistence of the active status.\n\n### Changes inside Set a status\n\nWork in src/components/StatusModal.jsx for new suggestions, Favorites or Recent behavior, emoji selection, duration options, validation, keyboard interactions, modal buttons, or modal layout.\n\nIf a feature needs shared state between App.jsx and StatusModal.jsx, keep the source of truth in App.jsx and pass the value or callback into StatusModal.\n\n### Supporting files\n\n- Add styling in src/App.css or the existing Tailwind classes.\n- Add dependencies through package.json using npm instead of editing package-lock.json manually.\n- Update README.md if the installation or run process changes.\n- Update this guide if the project structure or a fragile area changes.\n\n## Important data flow\n\nThe main status flow is:\n\n1. App.jsx loads the active status from localStorage using the key slack-active-status.\n2. The user opens StatusModal.\n3. StatusModal manages the temporary form values.\n4. Saving calls onSave(newStatus).\n5. App.jsx updates activeStatus.\n6. App.jsx writes the active status back to localStorage.\n\nThe modal also stores two collections:\n\n- slack-favorites — permanently favorited statuses.\n- slack-recents — recently used custom statuses.\n\nKeep the status object shape consistent:\n\n    {\n      emoji: "🔴",\n      text: "football",\n      duration: "Today"\n    }\n\nChanging this shape means checking every place that reads, writes, compares, or displays statuses.\n\n## Checks before submitting a change\n\nInstall dependencies:\n\n    npm install\n\nRun the linter:\n\n    npm run lint\n\nA passing lint run should finish without ESLint errors.\n\nRun the production build:\n\n    npm run build\n\nA passing build should complete successfully and create the dist/ directory.\n\nStart the development server for manual testing:\n\n    npm run dev\n\nThen check these main flows:\n\n1. Open Update your status.\n2. Select an emoji and enter a status.\n3. Change the duration.\n4. Save and confirm the active status appears.\n5. Refresh and confirm the active status remains.\n6. Reopen the modal and check Recent and Favorites.\n7. Favorite and unfavorite a status.\n8. Delete a Recent status.\n9. Open the emoji picker and press Escape.\n10. Close the modal with Escape and by clicking the backdrop.\n11. Try to save an empty status and confirm Save remains disabled.\n\nThere is currently no automated test suite. npm run lint and npm run build are the automated checks; the flows above are the main manual checks.\n\n## Fragile areas\n\n### 1. localStorage data\n\nThe active status, Recent list, and Favorites list are stored directly in browser localStorage. The code expects valid JSON and the current status object shape.\n\nStatusModal.jsx reads slack-favorites and slack-recents. App.jsx reads slack-active-status.\n\nIf the object structure changes, old data in an existing browser may no longer match the new code. When changing the structure, consider backwards compatibility or a migration.\n\n### 2. Recent/Favorite synchronization\n\nFavoriting and unfavoriting a status updates both Favorites and Recent. Be careful not to create duplicates or accidentally put a favorited status back into Recent.\n\n### 3. Duration and expiration display\n\ngetExpirationTime() calculates display text from values such as 30 minutes, 1 hour, 4 hours, Today, and This week.\n\nIt uses the browser's current time, so the absolute time can change between renders. These duration strings are also stored inside status objects, so changing them can break existing data and display logic.\n\n### 4. Modal event handling\n\nStatusModal.jsx registers global keydown and mousedown listeners and removes them when the modal unmounts. If this behavior changes, keep the cleanup logic or multiple handlers may accumulate after reopening the modal.\n\n### 5. Custom date/time UI\n\nThe Choose a start and end time controls are currently visual inputs and are not fully connected to the saved status. A real implementation would need to connect them to state and define how the selected dates and times are stored.\n\n## Before changing the UI\n\nThis is a visual rebuild, so small CSS changes can affect the input, expiration text, emoji picker, and action buttons. Check the modal in the browser after UI changes, including at smaller viewport widths.\n\nRecommended workflow:\n\n1. Make one focused change.\n2. Run npm run lint.\n3. Run npm run build.\n4. Test the affected interaction manually.\n5. Test the existing status, Recent, Favorites, and modal-close flows.\n\n## Related documentation\n\nSee README.md for the basic project setup and local development instructions.
